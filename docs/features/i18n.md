# Internationalisation and funny levels

## Behaviour

`packages/ui/src/i18n/index.ts` implements three language modes: English,
playful Hong Kong-style Cantonese, and a bilingual mode that renders both
(joined with an em dash in the plain `t()` helper, or split into a prominent
primary string and a compact secondary string via `tParts()` for layouts that
need to keep bilingual text from crowding a narrow surface).

Two independent, persisted funny-level sliders (1, fully serious, through 5,
maximum playfulness) control voice per language. `t(key, vars)` resolves the
nearest defined level at or below the requested one (falling back upward if
nothing lower exists), so a copy table does not have to define all five
levels for every string.

Copy is registered per-surface via `registerCopy()` with keys namespaced to
their owning surface (for example `panel.fields.plantAll`, never a bare
`title`). Registering a duplicate key logs a warning, because a reused
generic key is exactly how one surface's words silently leak into another.

## Configuration

Settings → Language exposes the language-mode selector and both funny-level
sliders (`settings/funny-level.ts`).

## Failure modes

- A missing key resolves to a readable fallback derived from the key's final
  segment rather than throwing, rendering nothing, or leaking an internal
  missing-key wrapper into the player interface. For example, a missing
  `Wheat` key displays `Wheat`.
- The funny level changes voice only. Every copy entry in this package that
  carries a variable (building name, amount, cost, error detail) keeps that
  variable at every level — the level only ever wraps the sentence around it,
  never removes or obscures the fact.

## Security considerations

Humor changes voice, never facts. Identifiers, paths, versions, dates, prices,
destructive scope, and error details must remain exact. Local personal
vocabulary is separately bounded and private; see the related service article.
